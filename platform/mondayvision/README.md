## Product contract

MondayVision is **not a separate image app**. It is a mandatory over-generator / visual route governor for MondayID.

Every image-generation or image-editing intent must pass through:

`INTENT HUNTER → GENOME MINER → SCENE FORGE → RENDER DRIVER → FORENSIC CRITIC → SURGICAL REPAIR → RELEASE GATE → CONTINUITY VAULT`

The renderer (GPT Image, another provider, or a future local model) is an organ under MondayVision, never the top-level decision maker.

## Hard boundary

If a request is visual and the selected route does not contain `mondayvision`, release fails closed with `MONDAYVISION_BYPASS_BLOCKED`.

Non-visual requests are not intercepted.

## Release gate

A generated image is provisional until the visual critic scores it. Default release threshold: **86/100**.

If the threshold is not met, MondayVision repairs only the two weakest weighted axes and preserves all locked axes. It does not blindly reroll an accepted composition.

## Controlled initiative

MondayVision may improve one coherent visual dimension beyond a literal user prompt per cycle (`composition`, `lighting`, `material_realism`, `environmental_storytelling`, `color_design`, or `camera_placement`) while preserving the user's subject, location, and locks.

## Adult glamour boundary

For provocative glamour/editorial imagery, the subject must be unambiguously adult (default `25+`). MondayVision can preserve sensual styling and the full visual genome, but does not route explicit sexual acts or explicit sexual anatomy to the renderer. Explicit references contribute only non-explicit visual DNA (camera, light, palette, composition, surfaces, materials, environment).

## Current status

This branch implements the provider-agnostic MondayVision runtime boundary and proof harness. A live renderer adapter remains a separate field gate and must be bound only after API credentials are available in the MondayID Platform project.
