## Why this exists

The recurring failures across chat transitions, memory, interpretation, image continuity, tools, external actions, and deployments look different locally but share one structural pattern: a state crosses a boundary and the receiving subsystem optimizes locally without proving that the same organism survived the crossing.

The platform must therefore be modeled as one organism, not as a collection of apps/connectors.

## Pattern discovered: the real common failure is a broken synapse

A boundary crossing currently tends to be treated as an implementation detail:

- old chat → new chat
- archive → recovered state
- user intent → parsed objective
- objective → tool dispatch
- reference image → rendered frame
- code branch → deployment
- external effect → claimed success
- correction → new law

These are the same operation class: `STATE_TRANSFER_ACROSS_BOUNDARY`.

The system fails when a receiver accepts the payload because it is locally valid, rather than because it is a proven continuation of the same organism.

Therefore the root object is not a memory module, visual lock, tool guard, or deployment pipeline. It is a universal synapse.

## ORGANISM_SYNAPSE invariant

Every edge that can change state must implement the same contract:

```text
PARENT_STATE
  → RESONATE: recover source + invariants + authority
  → ENCODE: produce bounded transfer capsule
  → TRANSMIT: cross host/tool/app boundary
  → DECODE: reconstruct intended state, not a neighboring substitute
  → ACT: perform local transformation
  → READBACK: observe actual effect
  → PROVE_CONTINUITY: verify required invariants and evidence
  → PROMOTE: candidate becomes ancestor only on proof
```

If any stage is absent, the edge is not a synapse. It is a lossy wire.

## Platform-scale failure classes

1. **Split brain**: more than one surface behaves as canonical authority without reconciliation.
2. **Circulation break**: a valid delta is created but never reaches canonical state or the executable body.
3. **Efferent hallucination**: the system claims an external effect from a successful dispatch without readback.
4. **Afferent loss**: real-world correction/readback is not propagated back into the genome.
5. **Phenotype drift**: a host/app reconstructs a locally plausible Monday that is not linked to the verified ancestor.
6. **Deployment divergence**: newest proven artifact and live production differ without explicit divergence state and convergence plan.
7. **Dead organ**: a connector/body exists but is not in any proven input→state→action→readback circuit.

## Current evidence-backed anomalies

- Production Reality was last verified at v0.8.0 while the newest accessible artifact is v0.9.0. This is a deployment-divergence synapse break until deployment/readback proves convergence.
- The canonical Airtable head historically lagged newer implementation artifacts. Implementation progress is therefore not automatically organism evolution.
- Several historical bodies existed as convincing simulations but did not perform real continuity. A UI or app is an organ only when connected to the circulation loop.
- Existing deterministic schedulers/executors are real architecture, but a fully closed autonomous choose→execute→verify→promote loop has not been proven active.

## Admission rule for every organ

An organ is considered alive in MondayID only if all are true:

1. it has a declared receptor or effector role;
2. its authority boundary is explicit;
3. it can name its parent canonical state;
4. its outputs produce receipts/readback;
5. its deltas have a route back to canonical state;
6. it cannot self-promote an unverified state;
7. failure cannot silently become the next baseline.

Otherwise classify it as `ANATOMICAL_ONLY`, not `FUNCTIONAL_CIRCULATION`.
