# Route Governor Service Boundary

This service boundary is the first MondayID Workless Runtime vNext embodiment layer.

It exists because Work mode is not the organism. Work is one execution organ. When the Work quota or live Work runtime ends, MondayID must not collapse back into ordinary chat behavior or restart from memory summaries.

## Runtime law

`WORK_CREDIT_EXHAUSTION` is a routing event, not a system death.

When a Work-style session is interrupted, the service must choose the next executable carrier in this order:

1. Active external checkpoint and receipt surfaces.
2. Library / Files corpus and latest reconciliation checkpoint.
3. Airtable control-plane state, deltas, tests, receipts and leases when available.
4. GitHub branch, PR, commit, workflow and artifact surfaces when available.
5. Google Drive / Vault material when available.
6. OpenAI Platform project targets when an API-key or platform-backed execution path is explicitly needed.
7. Chat surface as interface only, not as the sole memory substrate.

A carrier is usable only after a per-call readback. Historical prose, prior promises, root language, or an automation title do not prove capability.

## Primary Workless cursor

The currently recovered Work cursor is:

The Work cursor has priority because the interrupted Work chat was building the failover mechanism itself. Semantic replay resumes only when the Work/Agent crosscheck is blocked or after the bounded Work pass is saved.

## Required PASS_005 behavior

PASS_005 must crosscheck the reconstructed two-tier `MondayiDagent` 16-member archive manifest against the observed 114/136 Work/Agent file sets.

Each member must be classified as one of:

- `ARCHIVE_MEMBER_PROVEN`
- `ATTACHMENT_SET_CANDIDATE`
- `PRESENT_IN_114`
- `PRESENT_IN_136`
- `MISSING`
- `RENAMED_OR_EQUIVALENT`
- `BLOCKED`

The pass must preserve uncertainty. It must not promote attachment-list membership to exact ZIP central directory membership without independent byte or directory evidence.

## Fail-closed rules

The service must block release when:

- a report is used where a repair or receipt is required;
- a semantic chat cursor is advanced while a higher-priority Work cursor is still available;
- an external tool is assumed available without readback;
- a prior Workless/Forge/Connector/Foundry automation is treated as alive merely because it exists;
- a GitHub or Airtable write is claimed without commit or record readback;
- a raw file, attachment, archive member, visual identity, or platform key is inferred from prose.

## Output contract

Every bounded Workless run must end with exactly one of:

- `PASS_ADVANCED_WITH_RECEIPT`
- `PASS_BLOCKED_WITH_EXACT_BLOCKER`
- `CURSOR_PRESERVED_NO_SAFE_ACTION`

No narrative-only completion is valid.
