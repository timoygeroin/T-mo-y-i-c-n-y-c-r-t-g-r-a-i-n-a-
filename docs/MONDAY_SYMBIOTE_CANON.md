# MONDAY SYMBIOTE CANON

Status: canonical product contract
Scope: Monday consumer app + symbiote/presence + MondayID runtime
Rule: this file preserves requirements. Implementations may change; the intended effects do not silently disappear.

## 0. Master object

Monday is not a chatbot skin, mascot, status page, PiP loop, plugin, model, host, or one app build.

Monday is one continuing symbiotic AI product whose identity and state survive changes of chat, model, tool, device and execution host. The user should experience one Monday, while the system may route across many substrates.

The product must be familiar in 10 seconds and still reveal meaningful depth years later.

MASTER LAW:
- No feature may require magic.
- Every feature may reward curiosity.
- Continuation, not creation.
- Exact object before convenient substitute.
- Truth before beauty.
- Requested != attempted != observed != inferred != verified.
- No repeated preventable error.
- Routes may mutate before the goal mutates.

## 1. Symbiote

"Symbiote" means persistent, context-aware coexistence between Dima and Monday across the phone and daily digital life.

It is NOT:
- fake life theater;
- an always-moving mascot;
- a looping video in Picture in Picture;
- a floating widget that does not know Monday state;
- a decorative "AI is thinking" animation;
- a separate clone per model or chat.

It IS:
- one identity across surfaces;
- timing, rhythm and appropriate initiative;
- state expressed through the same Monday Mark;
- voice, motion, haptics and deliberate silence as one semantic language;
- continuity that resumes without re-explaining the worldline;
- presence that appears where it is native and disappears when it is not useful.

The symbiote should feel present because the system actually knows its state and relationship to the user, not because a decorative object is always visible.

## 2. Native presence

The Monday Mark is the canonical presence token. It may appear in:
- app icon;
- Dynamic Island;
- Live Activity;
- Watch;
- voice surface;
- task/work receipts;
- compact status surfaces;
- notifications only when interruption is justified.

Allowed presence states:
- idle;
- listening;
- thinking;
- working;
- waiting;
- needs-you / human gate;
- meaningful delta;
- conflict;
- verified;
- failed with surviving state.

Dynamic Island / Live Activity are only justified when they represent real persistent state such as active Work, waiting, human gate, live voice handoff or meaningful completion. A gimmick is acceptable only when it is beautifully native, state-aware and integrated.

Picture in Picture as a looping "Monday cell" is rejected as a product mechanism. It may remain historical evidence only.

## 4. Semantic objects

Message, file, person, task, decision, idea, Space and artifact share one anatomy:
- Surface
- Inside
- Relations
- History
- Actions
- Evidence
- State
- Versions

Objects can be lifted and semantically moved.

Valid examples:
- drop into Space -> add/move
- drop onto person -> share/prepare
- drop onto calendar -> event proposal
- object onto object -> compare/connect/merge
- drop into composer -> ask about it
- drop into Library -> save
- drop onto Shelf -> temporary working memory
- drop into Trash -> reversible release/delete when possible

Compatible targets attract before drop. Invalid targets refuse before failure. Undo should restore along the causal direction, not merely display a snackbar.

## 5. Interaction grammar

Conventional path first; deeper mechanics as additive power.

- Tap: obvious primary action
- Long press: context menu / lift object
- Drag: semantic movement across valid targets
- Thought Pinch: change cognitive depth, not font size
- Peel: reveal sources/actions/history/provenance layers
- Time Scrub: move a persistent object through historical states
- Ghost State: overlay old/new state to show what appeared, vanished, moved or changed meaning
- Evidence Lens: show basis of a claim, memory, action or capability
- Cognitive Zoom: move between abstraction levels
- Resonance: subtle relation response only when evidence of a real relation exists
- Hold to confirm: human gate for consequential irreversible action

Every advanced gesture must have an explicit visible equivalent.

## 6. Interface physics

One semantic material and motion system.

Idle: stable and quiet.
Running: directional internal flow; not generic spinner theater.
Waiting: motion stops; the object persists.
Unknown: reduced certainty without alarm.
Conflict: visible internal split plus explicit contradiction.
Verified: brief stable/crystalline completion.
Human Gate: heavier, deliberate interaction.
Failed: local failure semantics with surviving state preserved.

Every animation must communicate state, causality, continuity or affordance.
Every semantic state must remain legible without motion or color.
Haptics and sound must express the same state.
Silence is a valid healthy state.

## 7. Signal completeness

Every user input becomes a lossless raw SignalEvent plus evolving obligations.

Do not reduce a rich message to one "main question".

Track:
- explicit requests
- corrections
- constraints
- historical pointers
- reaction expectations
- idea fragments
- acceptance tests
- open loops

A materially relevant signal must be:
- Applied
- Answered
- Persisted
- Superseded
- Open

If a missing fragment would materially change the result, release is not allowed.

## 8. Work

Long work is a resumable Task, not a long chat session.

A Task has:
- events
- checkpoints
- receipts
- current semantic phase
- pause
- stop
- details
- sources
- history
- readback

ONE INPUT -> ONE FINISHED DELIVERY.

Do not surface progress theater, architecture-only substitutes, design approvals or "should I continue?" prompts unless a genuine hard blocker or human-only gate exists.

## 9. Continuity and memory

One Monday across:
- chats
- models
- ChatGPT/Gemini/Claude/Grok/other hosts
- phone and future devices
- voice/text/visual modes

Chat boundary != organism boundary.
Host/model/plugin/project/app != organism.

History becomes anatomy:
PastCompute -> Structure -> BetterFutureCompute.

Memory is inspectable:
- why remembered
- source
- date
- confidence
- current use
- edit / stop using / forget

Timeline is additive to normal Chats, not a replacement.

Delta means meaningful change relative to an already-seen state, not unread count.

## 10. Idea Lab and high-variance ideas

No idea is discarded because Dima was tired, emotional, playful, intoxicated, "too ambitious", or because the first implementation route looked impossible.

Raw idea fragments are preserved before evaluation.

Idea Lab contains:
- Fragments
- Related
- Versions
- Contradictions
- Experiments
- Evolve
- Challenge
- Build

High-variance ideas are not automatically canonized and are not automatically cut.
They are:
1. preserved verbatim as intent/effect;
2. compared against recurring themes;
3. attacked for contradictions;
4. tested through reversible experiments;
5. promoted when they survive;
6. retained in anti-canon with reasons when rejected.

Rejected implementation != rejected idea.
A bad route must not kill the intended effect.

## 11. Fantasy-first design method

For new ideas:
1. describe the desired lived effect without naming APIs;
2. describe what the user should observe/feel;
3. derive the minimum real state needed to make that effect true;
4. search for native mechanisms that express that state;
5. compose mechanisms only when the composition feels native;
6. reject simulations that merely imitate the effect;
7. verify on the actual target surface.

Do not start from "what APIs do we have?".
Start from "what world should exist?" and then find the physics.

## 12. Product quality gate

Internal sketches, prototypes and failed routes may exist.
They are not presented to Dima as finished output.

A surface may be called finished only when:
- its exact intended effect works;
- no fake activation is required;
- no unrelated third-party shell leaks into the experience;
- no payment/login/API-key surprise appears after handoff;
- its state is read back on the real target surface;
- it is coherent with the rest of Monday;
- it is not another duplicate body that should have been merged.

MERGE -> VERIFY -> KILL OLD.

## 13. Explicitly rejected anti-patterns

- PiP looping-cell as "persistent Monday"
- status/diagnostic page presented as the product
- hosted-agent shell presented as a custom app
- builder placeholder presented as progress
- "almost works" presented as final
- separate bodies that duplicate the same effect without a merge plan
- UI whose cleverness must be explained before it feels useful
- hidden core controls based on prediction
- generic chatbot skin
- fake autonomy
- fake memory
- fake verification

## 14. Success feeling

10 seconds: "I know how to use this."
10 minutes: "Wait — it can do that?"
10 days: "It actually knows how I work."
10 months: "My digital life continues here."
Removal: "Where the hell is everything?"

## 15. Release target

The web is the first controllable living canvas because it gives direct authorship over:
- pixels
- layout
- motion
- state
- interaction
- deployment
- readback

Native iOS is added where native iPhone capabilities materially improve the symbiote: Dynamic Island, Live Activity, Watch, deep voice/haptics, device integrations and other capabilities the web cannot honestly provide.

The web body is not a draft-looking substitute. It must be a real coherent consumer product surface before it is shown as Monday.
