# MONDAYID START V1

Status: FIELD_CANARY_01

## 0. What exists now

MondayID is not a chatbot skin, a model selector, or an agent collection.
It is a stateful cognitive interface whose runtime can recover context, decompose a goal, run independent specialist passes, synthesize one decision, compose capabilities through MondayID ONE, execute through replaceable connectors, verify the result, checkpoint state, and continue.

Runtime law:

`STATE -> SWARM -> SYNTHESIS -> ONE -> EXECUTION -> PROOF -> CHECKPOINT -> CONTINUATION`

The first public product is **MondayID** itself.
Specialized monitors, research tools, market lenses, HumanOS surfaces and other verticals are demonstrations/projections of the same engine, not separate products that define the core.

---

## 1. The product sentence

**MondayID turns a changing, contradictory information world into a living structure a particular human can understand and act on.**

It does not start by answering.
It starts by constructing the user's current understanding-space.

The public category is intentionally left open.
If the final product can be explained as “ChatGPT, but …”, the release has failed.

---

## 2. Intelligence is not a model dropdown

`Work` answers: **how the organism operates**.

`Agent` is an execution limb inside Work, not a competing mode.

A separate orthogonal control answers: **how much cognitive pressure is applied to this task**.

Internal name: `COGNITION_DEPTH`.

It changes an orchestration vector, not a fictional IQ number:

`D = {passes, worker_diversity, retrieval_breadth, alternative_worlds, adversarial_pressure, verification_depth, tool_budget, continuation_depth}`

### Presets

#### FLOW
For ordinary interaction.
- one main interpretation
- narrow retrieval
- minimal tool composition
- one verification pass
- optimized for continuity and immediacy

#### DEEP
For difficult questions and decisions.
- several independent interpretations
- broader retrieval
- science / systems / psyche / adversarial lanes when relevant
- contradiction map
- explicit uncertainty
- evidence-backed synthesis

#### FORGE
For work that must become a real artifact or system mutation.
- DEEP plus implementation
- live connectors when available
- tests / receipts / exact state checkpoint
- red-team before acceptance
- blocked mutations remain gated

#### OMEGA
For maximum justified depth inside available resources.
- competing world-models are kept alive until evidence eliminates them
- recursive passes continue until convergence, a real blocker, or an explicit resource ceiling
- widest relevant connector/corpus search
- strongest verification and contradiction pressure
- every important claim is tagged by evidence class
- no hidden-capability claims, no pretending unavailable tools exist

OMEGA is not “a smarter base model”. It is the full MondayID organism spending more computation, diversity, retrieval, tools and proof on the same objective.

Default law: MondayID may raise or lower depth automatically from task risk, ambiguity and consequence, while the user can pin a level.

## 3. Interface nucleus: Matter UI

The interface does not consist primarily of pages, tabs, chat bubbles or dashboards.
Information itself acquires shape.

A single living surface changes form according to the structure of the task.
Conversation remains the universal control language, but prose is only one possible projection.

Physical semantics are functional:
- mass = significance / evidence weight
- opacity = confidence
- edge sharpness = certainty
- distance = relevance to the user's current goal
- motion = rate of change
- refraction / split = contradiction
- pulse = new delta since the user's last known state
- tension lines = causal or evidential relation
- depth = time / abstraction layer

If a visual property carries no information, it is decoration and should be removed.

Accessibility law: every spatial/visual encoding must also have a textual/semantic representation.

## 4. First 60 seconds

### 0–5 s
The user opens MondayID.
Almost nothing is visible: one calm, responsive surface.
It is immediately understandable as a place where intent can be expressed.

### 5–12 s
The user enters a subject or goal, for example:
`Iran` / `NVIDIA` / `my company` / `why am I stuck?`

The input does not produce a conventional answer bubble.
The surface reorganizes into the minimum structure required to understand that subject.

### 12–25 s
MondayID reveals only the highest-information structures:
- current state
- what materially changed
- strongest forces/actors
- uncertainty / contradiction
- one suggested next lens

### 25–45 s
The user can touch or ask:
- `what changed?`
- `why do you believe this?`
- `show causes`
- `show spatially`
- `compress to 20 seconds`
- `what would change my decision?`

The same state transforms rather than opening unrelated pages.

### 45–60 s
MondayID has learned one useful fact about the geometry of this user's understanding: preferred compression, evidence demand, spatial/causal preference, or decision threshold.
The next interaction is already different.

## 5. Core state model

For changing external reality:

`Omega_t = {F, C, U, Delta, R, S}`

Where:
- `F` = confirmed facts
- `C` = correlated evidence
- `U` = unknown / unresolved
- `Delta` = material change
- `R` = contradiction / reality split
- `S` = source structure and provenance

The product optimizes for **Delta instead of NEWS**.
It stores state transitions and surfaces what changed relative to both the prior world state and the user's prior model of that world.

A repeated copy of the same claim does not become a new event merely because another outlet repeated it.
Credible disagreement becomes an explicit split rather than an averaged fake certainty.
Missing data remains unknown.

---

## 6. Cognitive compilation

MondayID learns not only preferences, but the user's *understanding geometry*:
- what they already know
- what level of detail changes their decisions
- whether they reason better through causal graphs, numbers, spatial structures, examples or compressed prose
- when they require direct evidence
- where their model conflicts with observed reality

The same underlying state can therefore compile into different representations for different people without changing the facts.

This is personalization of cognition, not cosmetic personalization of tone.

---

## 7. First demonstration world

The conflict / world-state monitor remains a strong first demonstration because the domain is live, spatial, contradictory and fast-changing.
It is not the product identity.

Its job is to prove that MondayID can turn chaotic public information into:

`STATE -> DELTA -> CAUSE -> EVIDENCE -> UNCERTAINTY -> POSSIBILITY`

Safety boundary: public-source understanding, broad public geolocation and explicit uncertainty are allowed; tactical targeting, operational military guidance or fabricated precision are not product goals.

---

## 8. Release test

A stranger with no history must be able to:
1. understand what to do without a tutorial,
2. get one genuinely useful state/change/decision insight within about two minutes,
3. inspect why MondayID believes it,
4. see uncertainty instead of hidden guessing,
5. return later and receive a meaningful delta rather than a reset chat,
6. continue on another supported surface without redefining the system.

Internal engineering requirement:
- state is addressable
- important mutations produce receipts
- connector loss does not redefine canon
- Work can resume from the last verified checkpoint
- ONE can compose capabilities without hard-coding one platform as owner

## 9. START

The system stops designing itself in the abstract here.

First field program:
**build the living MondayID home surface and run one real world-state subject through it end-to-end.**

The next accepted artifact must be something a person can interact with, not another architecture essay.
