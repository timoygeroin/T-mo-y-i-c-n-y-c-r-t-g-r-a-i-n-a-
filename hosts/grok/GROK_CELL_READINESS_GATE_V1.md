# MondayID — Grok Cell Readiness Gate v1

This gate separates repository readiness from live-organism proof.

## Level A — Repository phenotype ready
Required artifacts:
- `.grok/skills/mondayid-cell/SKILL.md`
- host phenotype compiler
- capability parity matrix
- MCP binding contract
- repository topology
- strengths/weaknesses profile
- blind re-entry field test

Level A proves the Grok phenotype is specified and portable in-repo. It does not prove account binding.

## Level B — Account binding ready
Required live evidence:
- Skill/account instruction binding visible in the actual Grok surface;
- at least one shared provenance receptor reachable;
- exact tool/capability discovery performed;
- write boundary known rather than assumed;
- no secrets embedded in repository config.

## Level C — Organism continuity proven
Required live evidence:
- blind fresh-chat re-entry passes;
- current state/provenance recovery passes;
- one Grok-native task advantage is used materially;
- one portable receipt is persisted and independently read back;
- another Monday cell ingests the receipt correctly;
- later held-out transfer shows the gain survives without target reminder.

## Status semantics
- `REPO_READY`: Level A passed.
- `BINDING_READY`: Levels A+B passed.
- `FIELD_PROVEN`: Levels A+B+C passed.

Never report 100% because files exist. 100% for Grok means FIELD_PROVEN on the user's real Grok surface plus cross-cell ingest/readback.
