## Weaknesses / risks to compensate
- Product availability differs by plan/surface/account; documentation is not live account proof.
- Many parallel Grok workers can be highly correlated; width is not independent evidence.
- Fast/live social information can be noisy and should not outrank stronger provenance automatically.
- Persistent Skill or Bot memory can drift from shared organism state if not reconciled against current provenance.
- Long-running workers can create a false sense of authority unless approval/write boundaries are explicit.
- Strong visual fluency can hide identity/material/canon drift unless role-lock and acceptance gates are retained.
- A repository branch alone cannot guarantee continuity in ordinary grok.com/mobile chats unless the Skill/connector/MCP/recovery path is actually bound there.
- Separate Grok products (chat, Build, Bot, Voice, API) may expose different tool surfaces; phenotype compilation must be per-surface, not assumed uniform.
